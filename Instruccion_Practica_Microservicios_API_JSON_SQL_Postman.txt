PRÁCTICA: MICROSERVICIO PARA RECIBIR JSON, TRANSFORMAR DATOS Y GUARDARLOS EN SQL

Asignatura: Sistemas de Información

OBJETIVO

Desarrollar una práctica sencilla donde los alumnos comprendan cómo un microservicio puede:

1. Recibir información desde una API o desde Postman.
2. Validar los datos recibidos.
3. Transformar una estructura JSON no relacional.
4. Convertir esa información en datos relacionados.
5. Insertar los datos en una base de datos MySQL o MariaDB.
6. Consultar el resultado directamente mediante SQL.
7. Actualizar el estatus de los registros mediante peticiones HTTP.

IDEA GENERAL

La práctica simula que una API externa entrega información en formato JSON.

El microservicio recibe esa información y la transforma para almacenarla en una base de datos relacional.

Flujo general:

API externa / Postman
        ↓
JSON
        ↓
Microservicio
        ↓
Validación
        ↓
Transformación
        ↓
Normalización
        ↓
MySQL / MariaDB
        ↓
Respuesta JSON
        ↓
Postman

EXPLICACIÓN

La estructura JSON puede contener objetos dentro de otros objetos.

En este ejemplo existen:

- Información general de la incidencia.
- Información del usuario.
- Información de la ubicación.
- Estatus.

El objetivo del microservicio es transformar esta información y almacenarla en tablas relacionadas.

FUNCIONES DEL MICROSERVICIO

Cuando el microservicio recibe el JSON deberá:

1. Verificar que exista el folio.
2. Validar que existan los datos obligatorios.
3. Buscar si el usuario ya existe.
4. Si no existe, crear el usuario.
5. Buscar si la ubicación ya existe.
6. Si no existe, crear la ubicación.
7. Buscar el identificador correspondiente al estatus.
8. Insertar la incidencia utilizando llaves foráneas.
9. Devolver una respuesta JSON.


RESPUESTA ESPERADA

Ejemplo:

{
  "resultado": "OK",
  "mensaje": "Incidencia registrada",
  "id_incidencia": 25,
  "estatus": "PENDIENTE"
}


IDEA IMPORTANTE

La estructura con la que recibimos la información no tiene que ser igual a la estructura con la que la almacenamos.

El microservicio puede recibir una estructura JSON anidada y transformarla en varias tablas relacionadas.

MODELO SQL PROPUESTO

CREATE TABLE usuarios (
    id_usuario INT AUTO_INCREMENT PRIMARY KEY,
    nombre VARCHAR(100) NOT NULL,
    correo VARCHAR(120) NOT NULL UNIQUE
);

CREATE TABLE ubicaciones (
    id_ubicacion INT AUTO_INCREMENT PRIMARY KEY,
    edificio VARCHAR(50) NOT NULL,
    salon VARCHAR(50) NOT NULL
);

CREATE TABLE estatus (
    id_estatus INT AUTO_INCREMENT PRIMARY KEY,
    nombre VARCHAR(30) NOT NULL UNIQUE
);

CREATE TABLE incidencias (
    id_incidencia INT AUTO_INCREMENT PRIMARY KEY,
    folio VARCHAR(30) NOT NULL UNIQUE,
    id_usuario INT NOT NULL,
    id_ubicacion INT NOT NULL,
    id_estatus INT NOT NULL,
    tipo VARCHAR(100) NOT NULL,
    descripcion VARCHAR(255) NOT NULL,
    fecha DATETIME DEFAULT CURRENT_TIMESTAMP,
    FOREIGN KEY (id_usuario) REFERENCES usuarios(id_usuario),
    FOREIGN KEY (id_ubicacion) REFERENCES ubicaciones(id_ubicacion),
    FOREIGN KEY (id_estatus) REFERENCES estatus(id_estatus)
);


CONSULTA PARA VER EL RESULTADO

SELECT
    i.id_incidencia,
    i.folio,
    u.nombre AS usuario,
    u.correo,
    ub.edificio,
    ub.salon,
    e.nombre AS estatus,
    i.tipo,
    i.descripcion,
    i.fecha
FROM incidencias i
INNER JOIN usuarios u
    ON i.id_usuario = u.id_usuario
INNER JOIN ubicaciones ub
    ON i.id_ubicacion = ub.id_ubicacion
INNER JOIN estatus e
    ON i.id_estatus = e.id_estatus;

IDEA CLAVE

El objetivo de la práctica no es desarrollar una interfaz gráfica.

El objetivo es comprender cómo un microservicio puede recibir información desde una API, procesarla, transformarla, relacionarla y almacenarla correctamente en una base de datos relacional.

Postman permite simular al cliente y probar las operaciones POST, GET y PUT sin necesidad de desarrollar todavía una interfaz web.
